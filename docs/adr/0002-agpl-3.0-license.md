# slusk is AGPL-3.0-or-later, because it is run as a network service

`LICENSE` holds the verbatim GNU Affero General Public License v3, copyright hyzr-dev.
The choice turns on one fact about how slusk is used: nobody runs it as a command that
exits. It is a daemon with a dashboard on `:9090` and an SSE API, which is precisely the
case AGPL section 13 exists for — a user who interacts with a modified slusk over the
network is entitled to that version's source, even though no copy of the binary was ever
handed to them. Under GPL-3.0 that same user gets nothing, because running a service is
not distribution.

The permissive alternatives were rejected for the reason the deciding issue (#380) named:
MIT and Apache-2.0 both permit repackaging slusk inside a closed product, and a
self-hosting tool that ends up as someone else's proprietary backend has lost the thing
that made it worth publishing.

## Consequences

- The decision is effectively final. Adding a licence is trivial; relicensing to anything
  more restrictive is not, since every copy already distributed keeps its own terms.
  Moving *outward* (AGPL → MIT) needs the agreement of every copyright holder, which is
  why the copyright line names a single holder rather than "contributors".
- Section 13 is an obligation, not a slogan: once the source is public, the interface
  should offer network users a way to reach it. Nothing in the UI does that yet.
- Organisations with a blanket policy against AGPL will not use or contribute to slusk.
  Accepted — the audience is other self-hosters, and the ecosystem slusk sits in (Gitea,
  Nextcloud, Jellyfin's neighbours) already runs on copyleft.
- The published image conveys the work, so `Dockerfile` copies `LICENSE` to
  `/usr/local/share/slusk/LICENSE` and declares
  `org.opencontainers.image.licenses`. distroless has no package manager to carry a
  copyright file for us.
- Nothing in the tree constrained the choice: there is no `vendor/`, no third-party
  copyright header in any tracked source file, and no vendored fonts or images. The Go
  dependencies are MIT, BSD-3-Clause and Apache-2.0; the npm ones are MIT. A copyleft
  dependency would have forced the GPL family — none exists here, so the full range from
  MIT to AGPL was genuinely open.

## Considered options

**GPL-3.0.** The same family as Lidarr, which slusk bridges to, and the obvious tribal
choice. Rejected because it leaves open exactly the gap that matters for this program: a
modified slusk offered as a hosted service triggers no obligation at all.

**MIT / Apache-2.0.** Widest adoption, the norm for Go tooling, and zero friction for
contributors. Rejected on the repackaging point above. Apache-2.0's patent grant is a real
advantage over MIT, but it does not change the outcome.

Recorded because the licence file itself shows only *what* was chosen, and the choice is
the kind that looks arbitrary in a year — the network clause is the whole argument, and it
is invisible from `LICENSE`.
